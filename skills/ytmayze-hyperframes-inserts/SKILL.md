## Keep real actions and sounds together

Use actual product/DAW capture and real brand assets for factual UI, selection, download, audition and drag actions. Generated scenery can frame the capture; it is not evidence that an interaction was captured. If an important real action is missing, mark it missing rather than drawing fake UI and calling it authentic.

Build a source-to-insert timing map and identify the authoritative audio. Declare the frame-range convention and verify that source durations, output durations and playback rates agree; half-open `[in, out)` ranges make the accounting straightforward. Preserve synchronized selection/audition/drag sounds and the audible demonstration. Include enough source context before an action and enough time afterward to understand its result; a correctly timed click alone does not make a one-frame UI change readable. Accelerate loading/waiting separately if useful; do not speed the sound preview merely to hit a duration. If target duration, source duration and protected audio conflict, resolve the allocation explicitly instead of silently dropping an action. An action timestamp is an event anchor, not a complete shot range. Choose its lead-in/result context from the surrounding real capture. Budget time for that context, taking it from loading or decorative holds where appropriate. When source context is unknown, mark the needed range as provisional rather than calling a one-frame selection readable.
