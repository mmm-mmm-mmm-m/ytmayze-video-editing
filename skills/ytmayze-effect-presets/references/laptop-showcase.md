# Editable shortcut showcase

Use this construction when the real shortcut or note-entry action benefits from explanation. It should clarify the action and provide a purposeful visual change, not fill every quiet passage.

Build from the creator's current design and media with suitable reuse permission. No device image, sound sample, screen recording, font or native template is included here.

| Replaceable slot | Coupled decision |
| --- | --- |
| Device shell and real screen | Display fit/corner pin, source range, readable result and clean mask edges |
| Key highlights | Actual platform/layout, modifiers, down/hold/release and action timing |
| Explanation | Correct command/action wording, accepted type style and readable margins |
| Sound | Synchronized cues from one device identity, without doubling existing cues |
| Layout and transitions | Destination aspect ratio, camera clearance and complete entrance/exit |

Use one cue map for screen action, highlights, caption and sound. Verify the shortcut against the application, OS and version; note-entry and commands need different mappings.

Keep ordinary host camera/screen layers accessible outside the composite. Use supported import or fresh IDs. Document whether media are consolidated or external and how moving them affects the project. A project that parses is not necessarily self-contained.

Review the entire entrance, action, release and exit with audio. Watch for mask leaks, flashes, cropped edges, text collisions and framing resets. Save a named variant with actual import/playback evidence.
